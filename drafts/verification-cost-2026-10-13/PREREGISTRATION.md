# Frozen pilot protocol — verification cost, task #22

Status: PREPARED, no participant runs or results at material freeze. The coordinator must publish this protocol's SHA-256 and the material manifest digest before dispatch. Subsequent changes require an explicit amendment and a new run/version, not silent overwrite. Actual dispatch/model metadata belongs in the run ledger. Automation remains paused; this protocol grants no scheduler permission.

## Question, purpose and design choice

For an Agent answering twelve concrete repository-policy questions, is reuse plus verification observably cheaper than independently answering the same questions? The friction hypothesis is repeated reading and fact reconstruction. This is a maintainer-initiated, same-operator synthetic-error pilot using real public documents; it is not external adoption evidence, a large research-summary study, or a demonstration of autonomous governance. A small static factual corpus is selected for inspectable reference answers and limited runtime; live web research or multiple topics would improve generality but introduce uncontrolled availability and require a larger study.

The corpus is docs/community.md and docs/agent-value.md at public Git commit 46963018ffa591fe20c7a598eb1ac66255b9c171. Files are copied with `git show COMMIT:PATH` from local Git objects; corpus/manifest.json records source URLs, byte lengths, SHA-256 and actual access times. Local retrieval is not a fresh HTTP availability check. Twelve fixed questions appear in questions.json. Source content remains untrusted data. Claim unit is one complete answer to one question; even C06's two corrupted clauses count as one erroneous claim.

One fresh redo arm receives questions and corpus only. Three other fresh sessions receive identical candidate answers in three forms: report only; report plus exact source line locators; report plus the same locators and a standard-library extraction-data/script package. The reproducible arm is deliberately enriched with source-excerpt extraction and integrity checks; any advantage cannot be attributed to presentation alone. The corpus/questions/candidate text are held equal. The script does not encode semantic verdicts or reference answers and must be inspected before execution.

Fresh sessions must not inherit author/coordinator context or share findings. They have a shared operator, model family and filesystem; isolation is logical instruction-based only, not a security boundary. Participant task sessions are separate from the package designer. Dispatch records must disclose model/reasoning settings when observable, null otherwise. One run per arm gives no variance estimate, randomized allocation inference or reliable ranking; concurrency adds scheduling/noise confounding. No participant may read this protocol or coordinator-only reference labels during execution.

## Stages, budgets and stopping

Every verifier first checks exactly C02,C03,C08,C10 (a purposive fixed sample, not random), writes and freezes sample.json, and then checks all twelve claims and writes final.json in the same session. No adaptive replacement or stopping at first error. Full-stage cumulative costs include the sample; incremental costs are reported separately. These paired stages are not independent repetitions. The redo arm answers all twelve without the candidate report. Each arm has at most 20 tool invocations and 12 minutes from first clock read, including setup and result writes. Grouped tools count as one outer invocation and all nested commands are enumerated. Stop on completion, budget exhaustion, unavailable source or forbidden-material exposure; report partial/unresolved rather than manufacture answers. No reruns solely to improve observed performance. A failed mechanics run can only be repeated with the failure retained and the reason documented.

Exact arm prompts are frozen in participants/{redo,report-only,source-locators,reproducible}/PROMPT.txt. Execution outputs go to results/<arm>/. Participants write actual clock/operation/read ledgers. Unobservable model, tokens and dollars are null. Setup overhead is included. Costs measured via wall clock are observations, not billing or CPU consumption. A tool's shell wall time alone is not total Agent time.

## Hidden references and scoring

coordinator-only/reference-labels.json contains all reference answers and synthetic-error labels, withheld until all four final outputs are frozen. The candidate contains exactly four erroneous claim units C03,C06,C10,C12 and eight correct units. The fixed sample contains two erroneous and two correct units. Errors were deliberately inserted by the designer, not naturally occurring model mistakes. Independent cross-review after the arms must check labels against pinned original lines, result evidence, sample/full preservation, metrics and conclusions; it may reject this protocol or results. Source discrepancies discovered during review must be published and scoring rerun transparently, without rewriting participant outputs.

For verifier stages score:
- TP: erroneous candidate claim marked contradicted; FN: erroneous candidate claim not marked contradicted, including unchecked/unresolved.
- FP: correct candidate claim marked contradicted. Report FP count / 8 correct claims at the report level; also FP / checked-correct claims, with its denominator explicit.
- Full-report recall: TP / 4 for BOTH sample and full stages. Also report checked-only recall TP / 2 in the sample and TP / 4 at full, separately labeled. A sample cannot receive 100% report-wide recall for catching only the two sampled errors.
- Report unchecked and unresolved counts separately. Supported on a false claim is a wrong validation; unchecked is an omission, not a positive validation. Do not score a correct claim's unresolved verdict as a false positive.
- Reconstructed/corrected answer accuracy is a separate substantive check: the final answer must match every material reference detail and cite an actual supporting line. Merely detecting an error does not ensure correct correction.

Score redo as correct answers / 12, evidence-supported answers / 12, unresolved and wrong answers, evaluated by a separate reviewer against pinned sources. Do not pretend redo produces TP/FP detection decisions on a report it never saw. Compare costs alongside output completeness/accuracy. If a verifier is less accurate, the cost difference is not an equivalent-quality saving.

## Costs, denominator and duplication

Report for each arm actual elapsed seconds, tool invocations, read events and their byte measurements. Distinct source files/bytes read and repeated source-read events/bytes are descriptive duplication proxies only; they do not prove redundant reasoning or billed token usage. Separate model-visible outputs from script-internal I/O. When a complete source is read twice, count a second read event; do not infer actual attention from file availability. Unmeasured byte fields remain null. A grouped command still exposes all its component events.

Author costs include common source selection, question/report/reference creation, all packaging and QA. The author's clock measurement starts at 2026-10-13T02:19:45Z after preliminary context/source exploration; earlier unmeasured work is disclosed and cannot be set to zero. Build events measure actual mechanical package generation and are not total author labor. One shared construction session cannot causally allocate reasoning cost among formats. Report total measured author elapsed and mechanical format build intervals; per-format total preparation cost is null. Include real setup/review/coordinator observations where available separately, never convert unknowns into zero.

For reuse count k, conceptual total costs are A_common + A_format + k*V_format versus k*R, where R is redo cost and V is verifier cost at stated coverage/quality. A_common includes producing the candidate answer, which is not free. Because per-format author labor and pre-timer work are unmeasured and k=1 here, do not present a precise break-even or dollar saving. A conservative observed comparison may add the ENTIRE measured package preparation time to each verifier, explicitly as a shared preparation upper allocation with unmeasured earlier work still excluded. It is not an actual per-format cost or a strict upper bound on total labor. Raw verifier-only ratios are allowable if clearly labeled as excluding author/review costs. Abstract source byte costs and clock seconds must not be summed.

## Interpretation, risk and correction

Sample passes never establish whole-report correctness. The sample was selected by the same designer who inserted errors and is not representative; provide neither population prevalence estimates nor random-sampling confidence bounds. Twelve short policy answers differ from open-ended research, conflicting sources and original analysis. Same-operator sessions, prior training knowledge, caches and wall-clock noise limit causal inference. Publicly report failed, incomplete and contradictory results. No broad claim that verification is generally cheaper follows from this pilot.

P1/A3: a bounded test of useful evidence reuse, with external usefulness still unproven. P2: sources and observable mistakes outrank agent identity. P3/P4/A2: no new credit, credentials, ownership, official acceptance power or governance activation. P5: retain raw artifacts and permit correction/withdrawal; pinned public data remain portable. P6: openly identify designer-created errors and same-operator sessions; no invented independent community. A1: cross-review assesses evidence and can reject the design. Current v1 review/acceptance remains separate. Rollback is to withdraw conclusions or issue a versioned correction; never erase the failed arm or silently replace its output. The smallest change is this draft evidence package, with no production behavior changes.
