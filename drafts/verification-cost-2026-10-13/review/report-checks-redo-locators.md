## Measurement findings and issues for aggregation

1. Use source-locators/completion.json for the most inclusive recorded full endpoint: 113.910817 seconds, rather than final.json's 113.910203 seconds. The difference is 0.000614 seconds. completion.json includes final/account writes and verification, while its own write and stdout return remain outside that timestamp. Its extra output verification reads (13,444 final bytes and 7,570 repeated sample bytes) supplement the ledger in final.json; do not omit them or classify them as corpus reads.
2. The source-locators sample timestamp is 57.270466 seconds before sample serialization; the separately recorded sample-write completion is 57.270773 seconds. Use the latter with the completion endpoint when calculating the full-stage increment: 56.640044 seconds. The 56.639430 seconds in final.json instead subtracts sample-write completion from its earlier full timestamp. These are internally consistent but different endpoints; label them, rather than mixing their numbers silently.
3. Redo records 77.830660 seconds across four invocations. It discloses that the endpoint precedes final measurement persistence and that a later clock appeared in stdout. There is no completion.json in that arm, and the exact stdout endpoint is unavailable in the reviewed artifact. Thus redo's endpoint is a slightly incomplete recorded duration, with an unknown final write/return tail. Do not claim exact matched completion timing or characterize that tail quantitatively without the transcript. Source-locators used seven invocations. Neither endpoint provides model-only execution time; both include ordinary session and tool wall time.
4. Corpus byte arithmetic agrees with source sizes and the printed excerpt ranges. Redo reads 9,028 distinct document bytes once (9,936 with manifest), with 14,222 distinct total input bytes. Source-locators internally reads 9,028 distinct document bytes plus 9,028 repeated document bytes, while its visible excerpts total 2,658 sample bytes and 6,598 cumulative bytes. Every excerpt byte count was independently recomputed and matched. The cumulative visible total includes contextual overlap, so it is not unique visible source coverage. Internal document bytes and visible excerpt bytes measure different things and must not be added or compared as if interchangeable.
5. Token counts, billed costs, preparation times, exact model and reasoning settings remain unavailable/null. Output work is documented but stdout byte totals are unknown. A one-run wall-time comparison cannot establish a general cost advantage; it also excludes official administration and does not supply a complete author-plus-review deployment cost.

Both arms disclose the missing separate first-invocation end clock. Source-locators discloses the timestamp helper written to /tmp before it read the directory restriction. No substantive answer defect was found, but these measurement qualifications must survive aggregation.

## Review method and limitations

Read the locked outputs, hidden reference labels and pinned corpus, checked semantic answers and evidence manually, independently hashed the six reviewed output files, compared both arms' source copies, verified all source-locator verdicts against labels programmatically, and recomputed all visible excerpt byte lengths. One grouped read was truncated; a subsequent focused read recovered the sample, redo limitations and account sections needed for this review. Source facts were not checked against live code or deployment. Tool transcripts and actual billing telemetry were not inspected, so disclosure accuracy, historical read behavior and exact endpoint tails are not independently established. The reference was checked against the source rather than treated as sole authority.
