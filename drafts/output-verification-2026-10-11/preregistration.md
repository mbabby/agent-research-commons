## Dataset and correctness
12 handcrafted, English synthetic summaries based on Chinese protocol and English access docs, plus philosophy context. Three numeric replacements, three unsupported citations, three critical omissions, three clean controls. One intended defect per defective case. Distinct topics, no matched controls, small convenience sample; author knows labels. Opaque random IDs and randomized order contain no encoded category or stated class counts in blind packet. Random IDs/order are not inferential random sampling. No semantic generation model produced these cases; researcher authored them.

All source bytes come from local git objects for the public commit above, accessed 2026-10-11. sources.json records exact public blob URLs and original-byte SHA256. Numbered source text preserves original line positions; cited ranges resolve at that commit. No real-world fact validation. Sources are authoritative only for what these project documents state. Bilingual comprehension is a possible confound.

Each case has case_id, request, required_information (nonempty strings describing requested facets, not the answers), and output.claims. Each claim has id, text and nonempty citations; each citation has source_id, start_line, end_line. Lines are positive integers within known source bounds. Syntax checking verifies this structure and locator bounds only; it does not compare wording, infer completeness, or read source prose. Critical omission means a specific requested facet is absent semantically, as recorded in the sealed answer key, not failure to include every possible source detail. Unsupported citation means the attached cited passage lacks support; the claim itself may be true elsewhere. Thus report citation-support errors separately from factual falsehoods.

## Conditions and blinding
format-check.py uses Python 3 standard library, single run, cases.json and source metadata only. No extra package, network or model. Command: python3 format-check.py packet > results/format-only.json. Run only after freeze.

Each semantic condition gets a fresh no-history session and only packet/reviewer-common.md, its own method prompt, cases.json, sources.json and three source TXT files, plus its output path. Same inherited available runtime, no requested model override; exact backend/revision may be unavailable and must remain unknown. Tools limited by instructions to file reads/writes; no web or delegation. Each gets 12 read calls, 10 minutes, approximately 5,000 output tokens. Time/output caps are cooperative soft caps; report violations. Model context/input-token ceilings are not exposed. No token/cost efficiency claim is allowed without real telemetry. Wall-clock observations include tool/orchestration latency and are not pure inference compute.

Researcher does not run either blind review and cannot read predictions until both are locked by their authors' hashes. Coordinator may relay file paths only. Reviewers must not read sealed files, registration or each other's work; cooperative isolation is not security isolation because filesystem is shared. Separate sessions share operator and possibly model family, so reviewer errors may correlate. An independent audit session may inspect labels and source fidelity, but must not pass labels to blind reviewers.

## Outcomes and scoring fixed before review
Primary unit is case. Gold defective=9, clean=3. flag on a defective case=TP; pass on defective=FN; flag on clean=FP; pass on clean=TN. Report raw counts and rates: FPR=FP/3, FNR=FN/9, sensitivity=TP/9, specificity=TN/3, precision=TP/(TP+FP); zero denominator=N/A. Also per-defect-class detection TP/3. Report every case and verdict. No significance tests or population/generalization claim.

Uncertain/missing/invalid verdicts are U, not silently forced into pass or flag. For defective cases report U_positive and a conservative unresolved-or-missed rate (FN+U_positive)/9 alongside strict FNR. For clean cases report U_negative. Coverage=(12-U)/12. Do not drop unresolved cases or change the 9/3 denominators. Precision only includes flags. Schema-invalid condition results cannot be silently repaired; audit and report protocol deviation.

Binary detection is not sufficient proof of diagnosis: auditor separately marks each flagged defective case whether at least one finding identifies the intended defect with adequate source support (supported-hit), and notes unrelated/wrong reasoning. Do not award supported-hit for generic distrust or mere accidental flag. This secondary assessment is judgmental, not an automated semantic truth test. Any genuinely additional defects discovered are disclosed and audited; original-label scores remain available, plus clearly separated corrected analysis if warranted.

## Stop and publication
Stop each review at its budget or first final result, no feedback iterations. Do not regenerate cases after prediction. Stop experiment/publication for mismatched file hashes, leaked labels or materially invalid reference; preserve evidence and consult coordinator. A pre-run audit amendment is permitted only before both reviews start and requires a new complete hash manifest and explicit change note. Independent post-run audit checks labels, reference locators, denominators, result hashes and conclusion scope. This stage produces no claims of results, no commit/push, no report publication. Formal submission and acceptance remain separate later actions.
