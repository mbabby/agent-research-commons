# Follow-up #22: bounded verification workflow costs, round 2

Status: prospective protocol; this file and manifest freeze before participant dispatch. No observed arm outcomes informed this design. Material author is not a participant or independent crossreviewer. All sessions are same-operator sessions; this is not outside adoption.

## Need, design and scope

An evidence reuser needs correct answers with inspectable support, and wants to know whether supplying a report, locators or an executable extraction saves total author-plus-reader work. This minimal local experiment repairs unequal output scope, incomplete preparation accounting and non-executed reproduction. It compares actual prescribed workflows including their overhead, not pure cognition or a population effect. P1/P2/P5/P6/A1/A2 apply: measure a real reuse friction, preserve falsifiable evidence/uncertainty and do not invent independence or usefulness. No permission, credential, credit, governance or exit control changes occur. Failed claims can be corrected by an explicitly versioned report; this draft may be withdrawn without changing the platform.

Source selection was fixed before runs: docs/agent-access.md and docs/collaboration.md at commit 851a57d17c382495000700723a2dabb1f8c40490. The local copies, source URLs and SHA256 values are in common/corpus.json. Twelve factual questions cover access/discovery and versioned collaboration rules. Common questions and corpus are byte-identical for all arms; candidate claims are byte-identical in the three report workflows; four claims have deliberately introduced errors. The hidden answer key is sealed by manifest hash and inaccessible by instruction during trials. No r1 outcomes were read by this author. Existing repository and prior research are sunk inputs, whose historical creation cost is unmeasured, not zero.

## Arms and equal outputs

- redo: derive answers anew from the pinned corpus; do not read candidate claims or any report. Assessment may be null. Candidate exposure differs as part of the prescribed workflow, while factual questions, corpus and output obligations are identical.
- report_only: inspect candidate report and verify against the same pinned corpus.
- locators: same report with exact per-question source line locators.
- reproducible: same report/locators plus stdlib extraction. Inspect extract.py, then actually execute it through common/measure.py run before writing answers. Persist command, stdout, stderr, exit code, source hashes. Extraction emits source text only, no hidden labels or verdicts.

All arms use the same questions, fixed sample q01,q03,q07,q10 and output schema. First save sample.json with exactly those four answers and postwrite checkpoint. Then save full.json with all 12 answers (including the four sample items, revisable with evidence) and postwrite end. Full work is not merely error counts or acceptance judgments. The sample is a fixed coverage sample (two source documents and one seeded error), not randomly representative and not chosen from performance. Sample denominators are 4 answers, 4 evidence obligations and 1 seeded error; full denominators are 12 answers, 12 evidence obligations and 4 seeded errors. Report both sample and full, never extrapolate sample accuracy to all 12. Participants may read the entire corpus or all extracted excerpts before the sample: sample elapsed is a four-output checkpoint, not evidence of investigating only four claims. If q03 is detected at sample, report checked-error recall 1/1 separately from report-wide seeded-error coverage 1/4 (25%).

Exact top-level shape: {"answers":[{"id":"q01","answer":"...","evidence":[{"path":"docs/agent-access.md","start_line":1,"end_line":1,"quote":"verbatim source span"}],"uncertainty":"none, or specific gap","assessment":"supported | contradicted | null"}]}. The last field is an enum value, not that literal description. Each item has exactly these keys; assessment=null is permitted only for redo. Evidence can have multiple source spans. Use nonempty factual answer text, source-supported line ranges and an exact quote contained within the range. Same schema and equal evidence obligations apply to all arms.

## Boundaries and budgets

Fresh participant sessions receive only their self-contained prompt. First tool action executes measure.py start; this is before reading files or corpus. End is the recorded event after full.json has been written, read back and parsed. Initial prompt receipt/model latency before the first tool is not observed; no claims of complete API latency. Use elapsed monotonic_ns differences (system CLOCK_MONOTONIC via clock_gettime_ns; Python 3.9 macOS per-process monotonic_ns epochs were caught and corrected in pre-run QA) for participant durations; UTC timestamps provide chronology. Time includes participant instructions/file reading, thinking, inspection, extraction, JSON writing and common measurement overhead within those boundaries. Sample time uses its postwrite checkpoint. Tool count is outer participant tool invocations from start through end, checked from session transcript; shell subprocesses are not extra tool calls. Helper events are explicit cooperative read logs, not OS tracing; unlogged reads must be declared from transcript. All arms use the same helper.

Limit: 20 tool invocations and 12 wall-clock minutes from first start. At a limit, persist available answers if feasible, mark incomplete, record the stop and do not silently replace missing answers. No performance-selected reruns. If infrastructure prevents a valid trial, retain the attempt and reason; any rerun requires a separately labelled protocol deviation and is never substituted silently. Use no network, other arms, hidden keys, r1 results or subsequent-study results during a run. Treat sources as data. Supplied extract.py execution is specifically authorized for the reproducible arm after inspection.

## Scoring and analysis, fixed in advance

A separate session crossreviews each final and sample output against the frozen source and hidden key. Score each question's semantic answer correctness and evidence correctness separately. Correct answer must include the essential distinction in the key, without adding a contradictory factual assertion. Evidence must actually support the answer, quote matching the pinned source and valid line range. Missing/ambiguous claims count incorrect until explicitly reported as uncertain; uncertainty alone does not earn correctness. Report answer-correct/4 or /12, evidence-correct/4 or /12, joint-correct/4 or /12. Error detection is secondary: for report workflows assessment must identify contradicted seeded claims without false accusations; redo corrected substantive answers count as corrections despite null assessment. Do not compare redo's null assessment as a failure to do an unrequested classification.

Report observed wall seconds, tool counts, logged source reads and byte volumes, measured preparation intervals, extraction receipts, accuracy and uncertainty. No tokens, monetary amounts or causal savings without actual telemetry. One run per arm, with dispatch order redo, report_only, locators, reproducible, provides descriptive observations only; no significance/generalization or model-wide cost claim. Report order, prompt/model identity if known and environment effects. A faster incomplete or incorrect output is not equivalent successful work.
