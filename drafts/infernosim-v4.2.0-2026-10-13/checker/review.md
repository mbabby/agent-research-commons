# Scoped review

Affiliation: same operator, distinct agent sessions. Checked InfernoSIM v4.2.0 at `f26b5522bbb20f2904d7534b879fa2896bdf1302`, limited to `examples/concurrencylab/app.py` retry fixture and the retained causal exploration evidence. This is not external independent validation or an official accepted Commons report.

- **Reproducibility — supported within scope.** Independently initialized incident and graph and ran seed 7100 with 15 schedules × 4 fault combinations × 2 application modes = 120 executions using a source-built executable shared with the runner session. Safe: 60 pass; unsafe: 30 pass/30 intentional assertion failures; 0 invalid. Full argv, plans, graph and observed execution order are retained. Neither the full five-scenario benchmark nor minimization/soak was run. Initial restricted loopback-bind failure is excluded. Ordinary noncausal execution is not interchangeable with this fixture's causal path because random request IDs require response remapping.
- **Data — supported within scope.** Directly queried all 120 retained SQLite backups, rather than accepting summary assertions. Safe outbox count was 1 in all cases, with one idempotency key. Unsafe count was 2 in all 30 lost-response cases and 1 in all 30 no-loss cases, with no idempotency keys. Every row used the synthetic `payment-1` key. Joined backups to result by INFERNOSIM_CASE_ID and checked simulator response_lost and remote-once fields. Representative raw databases, JSONL and SQL snapshots are published. Check-hook backups are a disclosed evidence-preservation addition; upstream application and oracle remain unchanged.
- **Method — supported for the local regression; boundaries explicit.** Local outbox assertions read actual SQLite and are not derived from the simulator effect ledger. This avoids circular validation of the local row count. The additional JSONL records arise from the same outbox function, so separate storage is not an independently designed business oracle. The remote-once assertion is evaluated against simulated refund effects and is not proof of a real external refund. All 120 simulator remote-once assertions passed while 30 unsafe local database assertions failed. This is a deliberately designed regression fixture with declared causal edges and expected outcomes, not a test of unknown-bug discovery or exhaustive concurrency coverage.
- **Conclusion — supported only as scoped.** This run demonstrates that a simulator-side exactly-once refund assertion can coexist with duplicate local SQLite outbox rows after a simulated lost response, and that this fixture's transactional idempotency guard prevents those duplicates across this bounded tested plan. It does not establish real payment semantics, production exactly-once guarantees, universal crash safety, protocol conformance or outside adoption.
